## Azure DevOps HTML Preview v0.4.4 — 修正內嵌預覽的頁內錨點連結

### 修正

- **完整預覽 (內嵌)**：點擊頁內錨點連結（`<a href="#section">`，例如左側導覽列、目錄）時，現在會正確捲動到目標位置。先前在內嵌模式下點了沒有任何反應，全螢幕模式則不受影響。
- **Markdown 預覽 (內嵌)**：側邊目錄與文章內的 `#錨點` 連結同樣恢復正常。
- **工作項目附件預覽**：HTML / Markdown 附件內的 `#錨點` 連結同樣恢復正常。
- 支援 `id` 屬性、舊式 `<a name>` 錨點、中文等經 URL 編碼的錨點名稱，以及 `#` / `#top`（回到頁首）。
- 點擊後預覽文件的 `location.hash` 會更新，並觸發 `hashchange` 事件，依賴網址 hash 切換內容的網頁（頁籤、單頁應用程式）也能正常運作。

- **完整預覽 (內嵌)**：沒有宣告 `<meta charset="utf-8">` 的 HTML 檔，中文不再變成亂碼。先前內嵌預覽會依瀏覽器語系的預設編碼解讀（繁體中文環境是 Big5），導致中文文字與中文錨點都對不上；現在一律以 UTF-8 顯示，即使檔案裡寫錯編碼宣告也一樣。工作項目附件預覽與 Tampermonkey 版同樣適用。

### 原因

內嵌預覽使用在 sandbox 中執行的 `blob:` 文件，Chrome 會靜默擋下這類文件的頁內跳轉（網址不變、不捲動、也不觸發 `hashchange`）。現在改由預覽自己捲到目標位置，並更新網址。

### 已知限制

- 內嵌模式下的錨點跳轉不會新增瀏覽器歷史紀錄：按「上一頁」會回到上一份文件，而不是上一個錨點位置。
- 不支援 CSS 的 `:target` 選擇器：依賴 `:target` 顯示或隱藏區塊的網頁，在內嵌模式下不會切換樣式。
- 網頁腳本自己以 `location.hash = …` 跳轉時仍會被 Chrome 擋下；這類網頁請改用「完整預覽 (全螢幕)」。
