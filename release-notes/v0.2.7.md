## Azure DevOps HTML Preview v0.2.7（未單獨發布，併入 v0.2.9 一起發布）— 新增 PDF 預覽

### ✨ 新功能

- **PDF 預覽 (內嵌)：在 Azure DevOps 檔案頁裡直接看 PDF**：
  打開 `.pdf` 檔案時自動以 **Chrome 內建的 PDF 檢視器**在檔案頁內顯示（與 HTML / Markdown 相同的自動預覽行為），
  自帶搜尋、縮圖側欄、列印、表單與文字複製等完整功能。
- **PDF 預覽 (全螢幕)**：開一個與來源視窗同位置、同尺寸的 popup 視窗，直接以 PDF 檢視器全螢幕顯示；
  不經過 10 MB 的暫存配額，**大 PDF 也能開**。
- 以 Git Items REST API 的二進位格式（`$format=octetStream`）取回原始檔，**支援 Git LFS 追蹤的 PDF**
  （與 ADO 自己下載的一樣取得實際內容，不是 LFS 指標檔）。
- 不引入 PDF.js：它需要 `eval` / `new Function`，Azure DevOps 的 CSP（沒有 `unsafe-eval`）下只有全螢幕模式跑得動；
  Chrome 內建檢視器兩種模式都可用、功能也更完整，擴充功能與 Tampermonkey 版都不必多打包一份函式庫。
- Tampermonkey 版同步（`@version` 0.2.7）。

### 🔄 行為變更

- `.pdf` 檔案頁的頁籤列右側會出現「PDF 預覽 (內嵌)」與「PDF 預覽 (全螢幕)」兩顆按鈕，
  並與 HTML / Markdown 一樣自動顯示內嵌預覽（每個檔案含分支只自動觸發一次；在 History / Blame 等頁籤不搶焦點）。
- **安全例外：PDF 的 iframe 不加 `sandbox` 屬性**（實測 sandbox 且無 `allow-same-origin` 會讓 Chrome 內建
  PDF 檢視器載不起來，blob URL 與直接 URL 皆然）。這不會降低安全性：PDF 由 PDFium 算繪、
  **不執行 PDF 內嵌的 JavaScript**，內容也不是 HTML、不會被當成可執行腳本的文件，
  所以碰不到 Azure DevOps 的 cookie / session。HTML / Markdown 的 sandbox 隔離完全不變。
- 全螢幕 PDF 走 popup + blob URL（與 HTML / Markdown 的擴充功能 sandbox 頁不同路徑）：
  PDF 不是 HTML 文件，且整份 PDF 放進 `chrome.storage.session` 會撞上 10 MB 配額。

### ⚠️ 已知限制

- 預覽內的「就地換頁」不含 `.pdf`：HTML / Markdown 內容裡的 PDF 連結仍開新分頁到 Azure DevOps 的檔案頁。
- PDF 內嵌的 JavaScript（表單自動計算等）不執行——Chrome 內建 PDF 檢視器的既有行為。
- 全螢幕 PDF 視窗顯示的內容來自開啟它的 Azure DevOps 分頁：來源分頁關閉後「重新載入」該視窗會失效
  （已載入的內容不受影響）。
- 超過 Azure DevOps Git Items API 回應上限的超大 PDF 抓取會失敗，錯誤會顯示在按鈕上。
- 其餘限制與 v0.2.6 相同。
