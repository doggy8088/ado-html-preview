## Azure DevOps HTML Preview v0.2.11 — 修正 Excel 預覽的表格顏色（紙張語意）＋視覺驗證規範

本版與 v0.2.10（新增 Excel 預覽）一起發布。

### 🐛 修正

- **深色模式下 Excel 儲存格文字不可讀的問題**：未指定字色的儲存格會吃到 App 主題的白字，配上檔案設計的
  淺色底（米黃／白）幾乎看不見。根因是預設字色跟著主題；現在改採**紙張語意**：
  **未指定字色 = 檔案的 dk1（通常黑）、未指定底色 = 檔案的 lt1（白）**，每個 `<td>` 都寫成顯式值——
  表格配色完全跟著「檔案」、不隨深淺色主題改變，Excel 裡是什麼顏色就顯示什麼顏色。
- 移除唯讀表格的斑馬紋與 hover 變色（會蓋掉檔案設計的底色）；hover 改為不改配色的疊色提示。

### 🔧 工程

- **新增測試套件 `make test`**（scripts/test-xlsx-core.mjs，輸入檔由 scripts/xlsx-fixture.py 產生）：
  行為斷言之外新增兩條**視覺驗證**硬性檢查——「紙張語意不變性」（深／淺建置的 `<td>` 樣式必須完全一致）與
  WCAG AA 4.5:1 對比（含預設值）；這組檢查就是為了抓這次的 bug。
- **AGENTS.md 新增「視覺驗證」規範**：深＋淺雙主題都要親眼看到成品、顏色以對比與 computed style 判定、
  截圖工具失效（回傳重複影像）時不得拿它當證據、沒親眼確認不得宣告「視覺 QA 通過」。
- `make lint` 納入 xlsx-core.js 與測試套件的語法檢查。

### ⚠️ 已知限制

- 本輪的截圖工具（兩個管道）有快取／權限問題，雙主題截圖證據不完整；已用檔案層級（每格顯式顏色）、
  瀏覽器 computed style（兩主題下 `<td>` 實際前景／背景一致）與放大裁切圖交叉確認修正結果。
