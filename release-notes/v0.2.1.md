## Azure DevOps HTML Preview v0.2.1 — 執行期才出現的圖片也能顯示

### 🐛 修正

- **網頁用 JavaScript 動態產生的圖片顯示成破圖**：
  有些網頁（例如把內容放在 JS 資料裡、切換選單時才用 `innerHTML` 組出畫面的導覽網站）的 `<img src="../analysis/…png">`
  不在原始 HTML 的標籤裡，而是執行期才出現。先前擴充功能只在渲染前掃描靜態的 `<img>` 並內嵌，
  看不到這些圖，瀏覽器又把相對路徑對照到 Azure DevOps 的網址去載入，結果只剩破圖與 alt 文字。
  現在預覽文件內會多一支小腳本，**按需載入**這些圖片。

### ✨ 運作方式

- 預覽中出現 `src` 為相對路徑的 `<img>`（不論是一開始就有、事後用 JS 插入、或事後改 `src`）時才處理，
  並且等圖片捲到視窗附近（約 400px 內）才向擴充功能要圖，再透過 Git REST API 從同一個 repo、同一個分支抓回來。
  `display:none` 的區塊與很遠處的圖片不會下載，切換頁籤或展開後才載入。
- 同一個路徑只抓一次，之後的重複使用直接取用快取。
- 這個機制同時適用於「內嵌」與「全螢幕」兩種模式、HTML 與 Markdown 預覽。
  全螢幕視窗沒有 Azure DevOps 的登入狀態，所以由原本開啟預覽的 Azure DevOps 分頁代為抓圖。
- 順帶改善：全螢幕模式因資源總量超過暫存額度而沒被內嵌的靜態圖片，現在也會在捲到時按需載入，不再是破圖。

### 🔒 安全設計

- 預覽內的網頁腳本無法藉此讀取 repo 內的任意檔案：只服務圖片副檔名（png / jpg / jpeg / gif / svg / webp / ico / bmp），
  路徑限制在同一個 repo；其他請求會被拒絕。
- 預覽 iframe 與 sandbox 頁仍然**沒有** `allow-same-origin`，無法接觸 Azure DevOps 的 cookie / session。

### 🔄 行為變更

- 網頁自己指定了 `<base href>` 時，相對網址由作者的設定決定，不啟用按需載入（與靜態資源內嵌的既有行為一致）。
- 單張圖片上限仍是 8 MB；抓不到的圖片會在 `<img>` 標上 `data-ado-img-failed`，並在預覽 iframe 的 console 顯示原因。

### ⚠️ 已知限制

- 只處理 `<img src>`；`srcset`、`<picture>`、CSS 的 `url()` 背景圖，以及腳本自己 `fetch` 的檔案仍無法取得。
- 全螢幕視窗的圖片由來源分頁代抓，來源的 Azure DevOps 分頁若已關閉或重新整理，尚未載入的圖片會載入失敗。
- 瀏覽器仍會先拿相對路徑對照 Azure DevOps 網址發出一次無效請求（回傳的不是圖片），之後才被替換成實際圖片；不影響結果。
- 其餘限制與 v0.2.0 相同。
